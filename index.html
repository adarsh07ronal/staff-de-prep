1 · What "validation" means here

Post-silicon validation (design evaluation): first silicon comes back from the fab and you prove it meets the datasheet in the real world — not in simulation. You build the eval board and test firmware/scripts, measure every spec across Process, Voltage, Temperature (PVT), and feed results back to Design (bugs, margin) and to Product/Test Engineering (so ATE production test matches the bench).

2 · Worked example — new SoC bring-up

New SoC: ARM Cortex-M + on-chip 16-bit SAR ADC + DDR3 + stereo audio DAC. First silicon just arrived.

  1. Rails first. No firmware. Confirm 1.8 / 1.1 / 3.3 V rails in tolerance, sequencing order correct on the scope, current draw sane (not shorted). Check internal 1.2 V reference on a test point.
  2. Clocks & reset. Probe crystal start-up, PLL lock, reset de-assertion timing.
  3. Debug connect. JTAG/J-Link, halt core, read device ID register. Load "blinky", see GPIO toggle on scope → you have a debug channel.
  4. Boot firmware. UART printf → SPI-flash boot → DDR3.
  5. DDR3 bring-up. Run write leveling / read training / Vref training. On failure: scope DQS vs clock, check fly-by routing, sweep training delay manually, build read eye diagram. Record timing margin (ps).
  6. ADC validation. Clean low-distortion sine in. Capture N samples with coherent sampling (integer, ideally prime, cycles per record). FFT → SNR, SINAD, ENOB, THD, SFDR. DC ramp → histogram method for INL/DNL, plus gain & offset error. Repeat over temp and Vdd. Plot ENOB vs temperature.
  7. Audio DAC validation. Digital full-scale tone via I²S → Audio Precision APx: THD+N, A-weighted dynamic range, frequency response flatness, channel crosstalk, PSRR (inject rail ripple, measure output). Level sweep to find THD+N knee.
  8. Serial interfaces. I²C 100 k/400 k/1 M: scope rise times vs spec mask, verify ACK. SPI: push to max rated clock, check setup/hold at slave.
  9. Power characterization. Active current at max clock, sleep/standby, IDDQ per rail, across temperature.
  10. Shmoo. Core: Vdd (0.9–1.3 V) × frequency (50–250 MHz), pass/fail at each point. Shape shows where the design is marginal and how much guardband the datasheet needs.
  11. Correlate. Hand INL/DNL/ENOB/power to PTE; when ATE reads 0.3 dB worse SNR, jointly isolate load board vs socket vs real limit, then set production limits with guardband.
  12. Feed back to Design. "DDR read window only 180 ps at hot/slow — below 250 ps target. Recommend adjusting default Vref code." That early debug-hook / DFT conversation is the JD's "engage early with Design teams".
3 · Concepts to have crisp

Characterization fundamentals

  • PVT corners; process split lots (SS/TT/FF), skew lots
  • Shmoo plots, guardbanding, margin
  • Datasheet parameter → test method → instrument mapping (the SCM plan mindset)
  • Bench vs ATE: why they differ (loading, cal, socket parasitics, thermal) and how you correlate

DFT / test study

  • Scan chains, ATPG, stuck-at vs at-speed
  • MBIST, LBIST, boundary scan (JTAG IEEE 1149.1)
  • IDDQ testing
  • Debug hooks to ask Design for: on-chip logic analyzer, register-readable status, analog test mux to a pin, clock/reset overrides

ADC / DAC / reference metrics your bridge

  • Static: INL, DNL, offset error, gain error, missing codes, monotonicity
  • Dynamic: SNR, SINAD, ENOB, THD, SFDR, IMD
  • Methods: coherent sampling, windowing (non-coherent), histogram/code-density for INL/DNL, servo loop for offset
  • Voltage reference: initial accuracy, tempco (ppm/°C), 0.1–10 Hz noise, PSRR, long-term drift
  • Sigma-delta ADC: oversampling, noise shaping, decimation filter (CIC + FIR) — you built exactly this on the STM32

ENOB = (SINAD − 1.76) / 6.02

High-speed interface compliance study

  • Eye diagram, mask testing, jitter decomposition (Rj / Dj / Tj, TJ@BER)
  • BER, bathtub curves, receiver stress / jitter-tolerance testing
  • Pre/de-emphasis, equalization (CTLE, DFE)
  • DDR3: write leveling, read/Vref training, tSU/tH, ODT · PCIe: CEM electrical, LTSSM link training, Gen1/2/3 · USB: eye masks, SI · HDMI/CSI: TMDS / D-PHY signalling

Lab instruments — what each measures

  • Real-time scope vs sampling / equivalent-time scope (when you need each)
  • BERT / pattern generator, arbitrary waveform generator (AWG)
  • Spectrum analyzer, phase-noise analyzer
  • SMU, precision DMM, electronic load
  • Audio Precision APx — THD+N, dynamic range, frequency response, crosstalk, level sweeps strongest match
  • Thermal: forced-air chamber, ThermoStream / Temptronic thermal forcing

Automation

  • SCPI over GPIB/USB/LAN, PyVISA, instrument driver abstraction
  • Test sequencing, data logging, automated PVT sweep loops, result DB + plotting
  • Frame your Python + Unity + CI work as reusable test infrastructure

  • MCU: ADuCM (Cortex-M), Maxim MAX32xxx; NPU: MAX78000 / MAX78002 (Cortex-M4 + CNN accelerator) — likely close to this BU

5 · Likely questions to drill

Technical

  • Explain a sigma-delta ADC. Why a decimation filter? (Lead with your CIC+FIR project.)
  • Measure the ENOB of an on-chip ADC on the bench? (Clean tone, coherent sampling, FFT, windowing, SINAD → ENOB.)
  • Measure INL/DNL? (Histogram / code-density method.)
  • Brand-new chip won't boot — walk me through debug. (Rails → sequencing → clocks/PLL → reset → JTAG ID → GPIO toggle → UART → boot source.)
  • What's a shmoo plot and how do you use it?
  • DDR3 read data unreliable — how do you find timing margin? (Sweep read delay / Vref, build eye, scope DQS vs clock.)
  • Why do bench and ATE results differ, and how do you correlate?
  • Automate a temperature characterization sweep? (Chamber/ThermoStream control + SCPI instrument loop + logging.)
  • Measure PSRR / crosstalk on an audio DAC?
  • What is coherent sampling and why a prime number of cycles?
  • What DFT features would you ask a design team to add for debuggability?

Behavioral (STAR)

  • A bug others missed → QNX resmgr bugs invisible in mock testing; or a real-hardware DDR/audio glitch
  • Bring-up under time pressure
  • Disagreement with a design engineer / driving a cross-team decision
  • A time your test caught something before it shipped → TiVo audio system testing, or Vogo QA on 15,000 units

Questions to ask them

  • What silicon is currently in the lab, and what's the next tape-out?
  • How is the SCM plan split between DE, PTE, and Design?
  • Where does the team sit on bench-vs-ATE correlation pain today?
  • How much of the validation flow is already automated vs built per-project?
  • Is the NPU work here closer to the MAX78000 family?
6 · Honest gaps + your plan

  • True PVT characterization / shmoo / corner-lot work — done functional and system validation, not full silicon characterization
  • High-speed electrical compliance (PCIe/USB/HDMI eye/jitter/BER) — understand the theory, haven't run the suites
  • ATE / PTE correlation — worked adjacent to production QA (Vogo), not on a tester
  • DFT internals (scan/ATPG/MBIST) — need to study; know JTAG/boundary-scan from the firmware side
  • IAR/Keil — used GCC/GDB toolchains; quick ramp
